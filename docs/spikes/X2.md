# Spike X2: world and loot (stable ids, runtime replication, loot call path)

2026-10-19/20, lane B. Scenarios `x2garage` / `x2zone` (`test/PacificTogetherTest/Scripts/scenarios/x2.lua`), headless,
port 7821, test pair `C:\PTLanes\laneB`, `main.dll` copied from the main checkout. The host opens the map with
`?listen`, spawns and possesses a `PDP_MainCharacter_C` for the guest 150 uu from its own (the `body` method), and
teleports both players next to each target, so relevancy hides nothing. Results are in
`local/test-results/<folder>`; folder names below are run ids. The zone was opened directly
(`open /Game/Maps/Wilderness/Forest/Wilderness_Forest_01?listen`), not reached through a run.

How the checks work: both sides list every actor of the world (class, path, spot, `RF_WasLoaded`, role, PendingKill).
The client writes its list to `%TEMP%\pt-x2-<port>-<tag>-client.txt` and the host diffs both (`PT|iddiff` lines). The
host announces each target in `...-targets.txt`; the client then looks for a new SimulatedProxy actor of that class
and waits for it to go. Hooks (`PT|call`, `PT|calls`) log the game's interaction and inventory functions on both sides.

Verdicts:
- **Q1 stable ids: partly free.** Level-placed actors have the same full path on both sides. Spawned actors do
  not: garage stations match by class + spot only, and zone loot is a separate random pick on each side.
- **Q2 runtime replication: works for showing and removing the host's actors, not as a state sync.**
  `SetReplicates(true)` makes a host actor appear on the guest within 4 s, and the host's destroy (ours or the
  game's pickup) removes it there within 0.15-1 s. A level-placed actor binds to the guest's own copy; a spawned
  one arrives as a second actor next to the guest's own. Guest copies run their own BeginPlay and roll their own
  contents. Attached actors land at 0,0,0.
- **Q3 call path: found for container opening, taking and world-item pickup.** Wreck scrap and anchors are known
  from the dumps only; the bot did not drive them.

Final runs: `20261020-113701-laneB-x2garage` 32/32, `20261020-114921-laneB-x2zone` 33/33 (also
`20261020-112703-laneB-x2zone` 33/33, `20261020-112221-laneB-x2garage` 31/31).

## Correction (2026-10-20): IsValid is not "alive"

Runs up to `20261020-110229` judged "gone" by `IsValid() and not IsActorBeingDestroyed()`. From Lua,
`IsActorBeingDestroyed()` read false in every run, and `IsValid()` stays true until garbage collection: the host's own
destroyed actor turned invalid 17.5 s and 33 s after `K2_DestroyActor` (`110229`, polled every 250 ms). The test now
uses the `PendingKill` internal flag (`HasAnyInternalFlags(0x20000000)`), which is set right after the call
(`pendingKill=true` in every destroy line since `111151`). Everything on day 1 about removal was measuring GC and is
replaced below: the 8-40 s delays, "a destroy of a bound level actor never reaches the guest", "`Pickup` did not
complete", and the guess that hooking `K2_DestroyActor` stopped Lua calls to it. `FindAllOf` also returns dead
actors: the guest's list in `114921` had 50 of 680 actors pending kill, the host's 0 of 1507.

### Q2: replicating at runtime (host: `SetReplicates(true)`, `SetReplicateMovement(true)`, `ForceNetUpdate()`)

- L, level-placed (garage `BP_RoadObstruct_Rock_Medium_9`, every garage run): **binds to the guest's own copy**. The
  guest's actor of the same path turns Role 1 (`samePathAsHost=true boundToOwnCopy=true`) and no second actor
  appears. The host's `K2_DestroyActor` removes it on the guest: 0.14 s (`113701`, check `client_L_gone`).
- L in the zone (`BP_RoadEnding_Concrete_02_C`, runs `195159`, `200027`): never became Role 1 on the guest within
  20 s. Not retried; the checks use L in the garage only.
- A, spawned on both sides (garage `BP_Garage_InventoryParts_C`): **arrives as a second actor** with a new 2^31 name
  (`samePathAsHost=false`, `sameClassNow` = own copies + 1); the guest's own copy stays (Role 3, alive after the
  host's destroy). In the zone the same-named guest lootable was a dead variant in every pending-kill-aware run
  (`ownObject=false` / own copy pending kill), so zone A behaves like C.
- C, a lootable only the host has alive (zone): arrives on the guest and **rolls its own contents there**. Host
  `CoolingBox_01_15` = Glass, Food, Plastic; its guest copy = Battery, Battery, Food, Glass (`114921`); same in `194408`. After
  the host took items the guest's copy still showed its own items.
- Position: lootables attached on the host (`ManageChildrenActor_*`, lockbox items in
  `BP_Spawn_Resource_ReactiveLockbox_*`) arrive at **0,0,0** (zone A in `112703`, `114921`). Unattached
  `BP_WorldItem_C` arrive at the host's spot. Detaching C on the host first (`K2_DetachFromActor`) gave the right spot
  in every run since `200730` except `200027`.
- B, a host-only world item (`BP_WorldItem_C`): arrives as a new actor (Role 1). On the guest its own BeginPlay ran
  `Set World Item Interactable(false)` and a `K2_DestroyActor` on itself, and the actor stayed (garage `191156`).
- Removal (pending-kill aware runs): host `K2_DestroyActor` -> guest copy pending kill in 0.1-1 s for L, A, C and B
  (`111632`, `112221`, `112703`, `113701`, `114921`; e.g. `114921` A 11:47:02.18 -> 11:47:02.49, C 50.90 -> 50.98,
  B 48:49.42 -> 48:50.41 at the 1 s poll). The game's own pickup removes it too: `Pickup Actor` destroyed B on the
  host and the guest's copy went (`112221`, `113701`).

### Q3: the game's call path (hooks; host bot = `PDP_MainCharacter_C:Command Interact` press, 600 ms, release)

- Highlight: `BP_HighlightManager_C` traces from the camera every tick and keeps `CurrentHighlight`; `SetHighlight`
  is called on change. Where the bot's aim missed, the target's highlight was forced on the manager every 10 ms
  while the button was held (`traced=false` in the log).
- Container (lootable) opening, every zone run: `Command Interact(true)` -> `Interact_WorldInteraction(true)` ->
  `BP_HighlightManager_C:HighlightPress(true)` -> `HighlightComponent:InteractPressed`; release ->
  `HighlightComponent:InteractReleased`. The lootable then runs `BP_Lootable_Base_C:OnInteractedWith`,
  `OnRollForOpenItems` (`RolledOnOpenItems` turns true and the contents can change), `SwitchToOpenedVisuals`,
  `UpdateInteractionOpened`, `UpdateVisualsForEmpty`, and `BP_InventoryManager_C:OpenInventoryContainer` +
  `OpenPlayerInventory` (the loot UI).
- Taking: the bot moved stacks with `UItemSlot:TransferStackIntoContainer(<backpack>)` (what the UI's slot transfer
  ends in; `ContainerCursor:TransferSlot` is hooked but was not used without UI input). `BoundOnEventItemCountChanged`
  fires on the lootable. `host_took_loot` passed in every zone run since `201418` (e.g. `112703`: 2 Food into the
  backpack, Scrap Steel left).
- World item pickup: `Command Interact(true)` on a world item goes to `Interaction_InventoryAction(true)`, not
  `Interact_WorldInteraction`. With a save-less host the backpack (`BP_InventoryManager_C.Inventory_Player`) has 0
  slots and gains them only as items go in (`AddSlot`, `SetNumSlots` change nothing). Then the press never reaches
  `HighlightComponent:InteractPressed` and nothing is picked up. Calling `InteractPressed`/`InteractReleased` on the
  item's `Highlight` directly took a lockbox item once (`194408`: `ItemContainer:AddItem`, then `K2_DestroyActor` on
  the world item) and plain `BP_WorldItem_C` never. `Pickup Actor(item, false)` took the garage's plain world item:
  `ItemContainer:AddItem`, the item in the backpack, the world actor destroyed (`112221`, `113701`:
  `pickup completed=true carried 0 -> 1`). On the zone's plain world items it did nothing (`112703`, `114921`:
  `carried 1 -> 1`, the backpack already held loot from C).
- Interaction lengths (`HighlightComponent`): lootables short=-1 long=0.51; world items short=0.32 long=0.38;
  `HoldTime` -1.
- Scrap / salvage and anchors were not present or not driven (no tool equipped, no anchors in Forest_01 opened
  directly). Their hooks were installed and never fired.

## Derived

- **Stable ids:** the full path is a free stable id only for loaded actors (`RF_WasLoaded`). Garage stations and
  storage match by class + spot. Zone loot has no reliable counterpart on the guest: the guest keeps its own
  random variant per prefab group, sometimes the same one. The host's actor is the only real one.
- Runtime replication can show host-only actors on the guest and removes them promptly, including the game's own
  pickup destroy. Pairing comes free (the replicated actor is the host's), but the replicated copy is a Blueprint
  running its own BeginPlay on the guest: own loot roll, own interactable state, own self-destroy attempts. It also
  lands at 0,0,0 when its host parent is not replicated. Replicate the look, position and existence; never trust its
  game state.
- Loaded actors bind on the guest (static NetGUID by path), and a host destroy of a bound loaded actor reaches the
  guest. So removal can go through replication for any actor the host replicates.
- The interaction chain to intercept on the guest is `PDP_MainCharacter_C:Command Interact` /
  `Interact_WorldInteraction` / `Interaction_InventoryAction` (input level), or `BP_HighlightManager_C:HighlightPress`
  with `CurrentHighlight` (which object). Those give "guest wants X with object Y". On the host the same object is
  driven through `HighlightComponent:InteractPressed`/`InteractReleased` (lootables) or `Pickup Actor` (world items),
  and the outcome is visible in `BP_Lootable_Base_C:*`, `ItemContainer:AddItem`/`RemoveItem` and `ItemSlot:Transfer*`.
- Any Lua "is it still there" test must check PendingKill, not only `IsValid`; `FindAllOf` results must be filtered
  the same way (the shipping mod too).

## Guesses

- The 0,0,0 position is the attachment: `AttachmentReplication` names a parent the guest cannot resolve
  (`ManageChildrenActor_*` is not replicated), so the actor keeps the origin. Detaching fixed it in all but one run.
- The prefab variant pick uses an unseeded or per-process random stream. A seed sync would not be enough anyway: the
  host's run spawn pass (crates, wrecks, barrels) never runs on the guest.
- With a real save the backpack has slots, and the player-path pickup (`Interaction_InventoryAction`) completes.

## Unknowns

- Why the zone road ending (loaded) did not bind while the garage rock did.
- The pickup path with a real inventory (needs a save in the test copy); `Pickup Actor` (to hands) vs backpack split.
- Scrap / salvage (`BP_ItemHarvestableComponent_C` on `BP_BaseTemplatePart_C` wreck parts and
  `BP_Spawn_ResourceBase_C`; the tool side `BP_ItemHarvesterComponent_C:DoSmash/DoCut/DoStrip/...`, products via
  `SpawnItems`) and anchors (`BP_Spawn_Anchor_Base_01_C : BP_Spawn_Resource_GrabBase_C`, `Long Grab Complete` ->
  `AnchorTaken`, `AddAnchorPulledTag`; `BP_InventoryManager_C.Inventory_AnchorStorage`, `DepositAnchorsAfterRun`):
  found in the dumps, not exercised.
- Whether `ItemSpawner`/spawn-point actors on the guest spawn more later.
- Garage storage contents live in `BP_InventoryManager_C` containers (`Inventory_Garage*`), a per-process manager,
  not in the storage actors: the guest's are empty and separate (not tested for writes).
- Whether hooking `Actor:K2_DestroyActor` interferes with anything (day-1 runs that hooked it measured GC, see the
  correction; the hook is left out).

## Recommendation for M4 (W1, W2)

1. **Ids.** Our id for an object is: the path for loaded actors; on the host, class + spot quantised to 10 uu (taken
   at BeginPlay, before physics moves it) + an ordinal for ties, for spawned ones. The host keeps an `id -> actor`
   table and sends the id with every state message. Do not use spawned actor names. For actors the host replicates,
   the replicated actor itself is the guest's handle; the id is only needed in messages.
2. **Suppress on the guest** (destroy, or hide + no collision + `Set World Item Interactable(false)` where destroy is
   refused), right after BeginPlay: its own lootables (the variant it kept per prefab group), `BP_SpawnPoint_C` /
   `BP_ItemSpawner_C` / `BP_LeafSpawner_C` products, world items and resources it spawns in zones, its local car and
   car parts (M3), and garage storage UI contents (shown from host state). Only actors with Role 3 (local); replicated
   ones (Role 1) stay.
3. **Show host-only spawned actors by replication.** On the host, for every actor of the loot classes (lootables,
   world items, wreck templates and parts, lockboxes, gas barrels, anchors), set replicate + replicate movement after
   BeginPlay, detaching from non-replicated parents first. On the guest, ignore the replicated copy's own state: on
   arrival, clear its container and turn off its own roll / self-destroy (hook its BeginPlay paths). Removal follows
   the host's destroy (measured 0.1-1 s). Fallback if replicated Blueprints keep misbehaving: a spawn manifest message
   (class, transform, id) with guest-side spawning.
4. **Everything else goes through intents.** The guest's interaction is caught at `Command Interact` /
   `HighlightPress` with the target id. The host runs `InteractPressed`/`InteractReleased` on its own object
   (lootables), `Pickup Actor` (world items), or `ItemSlot:TransferStackIntoContainer` for transfers, and broadcasts
   the result: opened, contents (archetype list), empty, taken. The guest's loot UI shows the host's contents. The
   guest's backpack lives on the host (P3/P5); picked-up items go there.
5. **Level-placed actors** (rare for loot) keep their path id. If the host replicates them they bind to the guest's
   copy and a destroy reaches it; other state changes (opened) are messages.
6. Keep `x2zone` / `x2garage` as the W1/W2 regression tests once suppression exists. Add checks that the guest has
   no own live lootables and the host's replicated ones sit at the host's spots with the host's contents.
