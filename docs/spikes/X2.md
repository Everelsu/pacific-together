# Spike X2: world and loot (stable ids, runtime replication, loot call path)

2026-10-19, lane B. Scenarios `x2garage` / `x2zone` (`test/PacificTogetherTest/Scripts/scenarios/x2.lua`), headless,
port 7821, test pair `C:\PTLanes\laneB`, `main.dll` copied from the main checkout. The host opens the map with
`?listen`, spawns and possesses a `PDP_MainCharacter_C` for the guest 150 uu from its own (the `body` method), and
teleports both players next to each target, so relevancy hides nothing. Results are in
`local/test-results/<folder>`; folder names below are run ids. The zone was opened directly
(`open /Game/Maps/Wilderness/Forest/Wilderness_Forest_01?listen`), not reached through a run.

How the checks work: both sides list every actor of the world (class, path, spot, `RF_WasLoaded`, role). The client
writes its list to `%TEMP%\pt-x2-<port>-<tag>-client.txt` and the host diffs both (`PT|iddiff` lines). The host
announces each target in `...-targets.txt`; the client then looks for a new SimulatedProxy actor of that class.
Hooks (`PT|call`, `PT|calls`) log the game's interaction and inventory functions on both sides.

Verdicts:
- **Q1 stable ids: partly free.** Level-placed actors have the same full path on both sides. Everything spawned
  at runtime does not, and in zones the guest's loot is not even the same objects.
- **Q2 runtime replication: works for showing the host's actors, not as a sync mechanism.** `SetReplicates(true)`
  makes a host actor appear on the guest. A level-placed actor binds to the guest's own copy; a spawned one arrives
  as a second actor next to the guest's own. Guest copies run their own BeginPlay and roll their own contents.
  Attached actors land at 0,0,0.
- **Q3 call path: found for container opening and world-item pickup.** Wreck scrap and anchors are known from the
  dumps only; the bot did not drive them.

## Observations

### Q1: names and spots (host vs guest, same map)

- Garage, 6 runs (`20261019-191156` ... `20261019-205039-laneB-x2garage`): all 59 loaded actors match by path and
  spot (`iddiff garage loaded: same=59 moved=0 renamed=0 hostOnly=0 clientOnly=0`). Runtime-spawned actors: 228-230
  are at the same spot under different names, 8 share a name. Every garage loot-like actor is spawned, none loaded:
  `BP_Garage_InventoryContainer_StarterStorage_C` x2, `BP_Garage_InventoryParts_C` x4,
  `BP_Garage_InventoryExpansion_01_C` x4, `BP_Garage_LuckyJunkHeap_C`, `BP_Storage_Trunk_Base_C`, gas pump handles.
  All 14 are on both sides at the same spot under different names, e.g. host
  `BP_Garage_InventoryParts_C_2147469352` = client `BP_Garage_InventoryParts_C_2147478838`.
- Spawned names count down from 2^31 (`_2147469352`), one counter for every class (UE's fast-path unique names in
  cooked builds), so the number depends on everything the process spawned before.
- Garage host-only (spawned by host-only spawners, absent on the client): template cars and their parts,
  `BP_Lootable_Crate_*` (3-4 in some runs, none in others), `BP_Container_*`, `BP_Spawn_Resource_LightArray_*`,
  `BP_WorldItem_C` x2.
- Zone (`20261019-194408`, `-195159`, `-200027`, `-200730`, `-201418`, `-202033`, `-202621`, `-203341`,
  `-204004-laneB-x2zone`): 181 loaded actors match by path and spot. 3 `BP_ClumpedArea_Residental_PrePlaced_C` are
  loaded on the client only. Zone loaded actors are foliage structures, road endings, site spawners,
  vista and landscape. No loot is level-placed.
- Zone loot that both sides spawn (spawn points, `BP_SpawnPoint_C` 23/23 same path) is a separate roll on each side
  (`194408`). Lootables of the same class sit at different spots on host and guest, metres to tens of metres apart.
  The one per class that matches by name and spot (`BP_Lootable_CoolingBox_40`, `BP_Lootable_Backpack_Civilian_0`)
  still has different contents: host `CoolingBox_40` = Plastic, Food; client = Food, Battery, Battery, Food.
  Spawned zone names come from prefab templates (`BP_Lootable_CoolingBox_01_10`), not the 2^31 counter, and repeat
  across runs.
- Movement base: the guest's character stood on a client-only actor; the host logged
  `UPackageMapClient::InternalLoadObject: Unable to resolve default guid from client: PathName: SM_Basketball_Court2_29`
  dozens of times (`204004`, host engine log).

### Q2: replicating at runtime (host: `SetReplicates(true)`, `SetReplicateMovement(true)`, `ForceNetUpdate()`)

- L, level-placed (garage `BP_RoadObstruct_Rock_Medium_9`, runs `193716`, `204537`, `205039`): **binds to the
  guest's own copy**. The guest's actor of the same path turns Role 1 (`samePathAsHost=true boundToOwnCopy=true`) and
  no second actor appears. After the host's `K2_DestroyActor` the guest's copy stayed (25-45 s watched).
- L in the zone (`BP_RoadEnding_Concrete_02_C`, runs `195159`, `200027`): never became Role 1 on the guest within
  20 s.
- A, spawned on both sides (garage `BP_Garage_InventoryParts_C`; zone cooling boxes and backpacks with the same name
  on both sides): **arrives as a second actor** with a new 2^31 name (`samePathAsHost=false`, `sameClassNow` = own
  copies + 1). The guest's own copy stays (Role 3).
- C, a host-only lootable (zone `BP_Lootable_Crate_Generic_Government_Site_15`, cooling boxes, `BP_Lootable_Crate_Junk_C`):
  arrives on the guest and **rolls its own contents there**. Host Tape, Glass, Plastic, Glass, Glass; guest Glass,
  Scrap Steel, ... (`194408`). After the host took items the guest's copy still showed its own items.
- Position: lootables and lockbox items that are attached on the host (`ManageChildrenActor_*`,
  `BP_Spawn_Resource_ReactiveLockbox_*`) arrive at **0,0,0** (`195159`, `200027`, `202621`). Unattached
  `BP_WorldItem_C` arrive at the host's spot. Detaching C on the host first (`K2_DetachFromActor`) gave the right spot
  in `200730`, `201418`, `202033`, `203341`, `204004`, and 0,0,0 once (`200027`).
- B, a host-only world item (`BP_WorldItem_C`, lockbox items): arrives as a new actor (Role 1). On the guest its own
  BeginPlay ran: `Set World Item Interactable(false)` and a `K2_DestroyActor` call on itself, and the actor stayed
  (garage `191156`).
- Removal: in runs `191156`-`204537` the test mod had a hook on `/Script/Engine.Actor:K2_DestroyActor`. In those runs
  the host's Lua `K2_DestroyActor` never removed anything on the guest (`client_*_gone` FAIL). One apparent pass
  (`193716`) happened right after both players teleported away (relevancy). `SetLifeSpan(0.1)` did no better
  (`204004`). Without that hook (`205039`), the guest's replicated A went **8.4 s after** the host's destroy, with
  no teleport. `IsActorBeingDestroyed()` read false right after the call in every run, with or without the hook.
- The game's own pickup removed a lockbox world item with `ItemContainer:AddItem` then `K2_DestroyActor`, and the
  guest's copy went away (`194408`).

### Q3: the game's call path (hooks; host bot = `PDP_MainCharacter_C:Command Interact` press, 600 ms, release)

- Highlight: `BP_HighlightManager_C` traces from the camera every tick and keeps `CurrentHighlight`; `SetHighlight`
  is called on change. Where the bot's aim missed, the target's highlight was forced on the manager every 10 ms
  while the button was held (`traced=false` in the log).
- Container (lootable) opening, `194408` and later zone runs: `Command Interact(true)` ->
  `Interact_WorldInteraction(true)` -> `BP_HighlightManager_C:HighlightPress(true)` ->
  `HighlightComponent:InteractPressed`; release -> `HighlightComponent:InteractReleased`. The lootable then runs
  `BP_Lootable_Base_C:OnInteractedWith`, `OnRollForOpenItems` (`RolledOnOpenItems` turns true and the contents can
  change), `SwitchToOpenedVisuals`, `UpdateInteractionOpened`, `UpdateVisualsForEmpty`, and
  `BP_InventoryManager_C:OpenInventoryContainer` + `OpenPlayerInventory` (the loot UI).
- Taking: the bot moved stacks with `UItemSlot:TransferStackIntoContainer(<backpack>)` (what the UI's slot transfer
  ends in; `ContainerCursor:TransferSlot` is hooked but was not used without UI input). `BoundOnEventItemCountChanged`
  fires on the lootable. `host_took_loot` passed from `201418` on (2 tapes into the backpack).
- World item pickup: `Command Interact(true)` on a world item goes to `Interaction_InventoryAction(true)`, not
  `Interact_WorldInteraction`. With a save-less host the backpack (`BP_InventoryManager_C.Inventory_Player`) has 0
  slots and gains them only as items go in (`AddSlot`, `SetNumSlots` change nothing). Then the press never reaches
  `HighlightComponent:InteractPressed` and nothing is picked up. Calling `InteractPressed`/`InteractReleased` on the
  item's `Highlight` directly gave `ItemContainer:AddItem` (+ `ItemSlot:AddItem`). It completed once: lockbox into the
  backpack, world actor destroyed (`194408`). `Pickup Actor(item, false)` put a plain item into the hand slot
  (`201418`).
- Interaction lengths (`HighlightComponent`): lootables short=-1 long=0.51; world items short=0.32 long=0.38;
  `HoldTime` -1.
- Scrap / salvage and anchors were not present or not driven (no tool equipped, no anchors in Forest_01 opened
  directly). Their hooks were installed and never fired.

## Derived

- **Stable ids:** the full path is a free stable id only for loaded actors (`RF_WasLoaded`). Garage stations and
  storage match by class + spot. Zone loot has no counterpart on the guest at all, so no id scheme can pair it with
  the guest's local actors. The host's actor is the only real one.
- Runtime replication can show host-only actors on the guest. Pairing then comes free (the replicated actor is the
  host's), but the replicated copy is a Blueprint running its own BeginPlay on the guest: own loot roll, own
  interactable state, own self-destroy attempts. It also lands at 0,0,0 when its host parent is not replicated.
  Replicate the look and the position; never trust its game state.
- Loaded actors bind on the guest (static NetGUID by path). Destroying a bound loaded actor did not reach the guest,
  so removal of level-placed things needs our own message.
- Removal of spawned replicated actors works (8 s, `205039`) once nothing hooks `K2_DestroyActor`. The test mod must
  not hook it, and neither may the shipping mod.
- The interaction chain to intercept on the guest is `PDP_MainCharacter_C:Command Interact` /
  `Interact_WorldInteraction` / `Interaction_InventoryAction` (input level), or `BP_HighlightManager_C:HighlightPress`
  with `CurrentHighlight` (which object). Those give "guest wants X with object Y". On the host the same object is
  driven through `HighlightComponent:InteractPressed`/`InteractReleased` (the component's own native logic), and
  the outcome is visible in `BP_Lootable_Base_C:*`, `ItemContainer:AddItem`/`RemoveItem` and
  `ItemSlot:Transfer*`.

## Guesses

- The 0,0,0 position is the attachment: `AttachmentReplication` names a parent the guest cannot resolve
  (`ManageChildrenActor_*` is not replicated), so the actor keeps the origin. Detaching fixed it in 5 of 6 runs.
- The guest's zone spawn points roll from an unseeded or differently seeded stream. A seed sync would not be enough
  anyway: the host's run spawn pass (crates, wrecks, barrels) never runs on the guest.
- Hooking a native UFunction with UE4SS (`RegisterHook("/Script/Engine.Actor:K2_DestroyActor")`) breaks calls to it
  from Lua. Only `K2_DestroyActor` was seen affected; the other native hooks (InteractPressed, AddItem) did not stop
  their functions.
- With a real save the backpack has slots, and the player-path pickup (`Interaction_InventoryAction`) completes.

## Unknowns

- Why the zone road ending (loaded) did not bind while the garage rock did; whether a destroy of a bound loaded actor
  can reach the guest at all (startup-actor destruction info).
- The pickup path with a real inventory (needs a save in the test copy); the `Pickup Actor` (to hands) vs backpack
  split.
- Scrap / salvage (`BP_ItemHarvestableComponent_C` on `BP_BaseTemplatePart_C` wreck parts and
  `BP_Spawn_ResourceBase_C`; the tool side `BP_ItemHarvesterComponent_C:DoSmash/DoCut/DoStrip/...`, products via
  `SpawnItems`) and anchors (`BP_Spawn_Anchor_Base_01_C : BP_Spawn_Resource_GrabBase_C`, `Long Grab Complete` ->
  `AnchorTaken`, `AddAnchorPulledTag`; `BP_InventoryManager_C.Inventory_AnchorStorage`, `DepositAnchorsAfterRun`):
  found in the dumps, not exercised.
- Whether `ItemSpawner`/spawn-point actors on the guest spawn more later.
- Garage storage contents live in `BP_InventoryManager_C` containers (`Inventory_Garage*`), a per-process manager,
  not in the storage actors: the guest's are empty and separate (not tested for writes).

## Recommendation for M4 (W1, W2)

1. **Ids.** Our id for an object is: the path for loaded actors; on the host, class + spot quantised to 10 uu (taken
   at BeginPlay, before physics moves it) + an ordinal for ties, for spawned ones. The host keeps an `id -> actor`
   table and sends the id with every state message. Do not use spawned actor names.
2. **Suppress on the guest** (destroy, or hide + no collision + `Set World Item Interactable(false)` where destroy is
   refused), right after BeginPlay: its own lootables, `BP_SpawnPoint_C` / `BP_ItemSpawner_C` / `BP_LeafSpawner_C`
   products, world items and resources it spawns in zones, its local car and car parts (M3), and garage storage UI
   contents (shown from host state).
3. **Show host-only spawned actors by replication.** On the host, for every actor of the loot classes (lootables,
   world items, wreck templates and parts, lockboxes, gas barrels, anchors), set replicate + replicate movement after
   BeginPlay, detaching from non-replicated parents first. On the guest, ignore the replicated copy's own state: on
   arrival, clear its container and turn off its own roll / self-destroy (hook its BeginPlay paths). Removal follows
   the host's destroy. A fallback, if replicated Blueprints keep misbehaving: a spawn manifest message
   (class, transform, id) with guest-side spawning.
4. **Everything else goes through intents.** The guest's interaction is caught at `Command Interact` /
   `HighlightPress` with the target id. The host runs `InteractPressed`/`InteractReleased` on its own object, or for
   transfers `ItemSlot:TransferStackIntoContainer`, and broadcasts the result: opened, contents (archetype list),
   empty, taken. The guest's loot UI shows the host's contents. The guest's backpack lives on the host (P3/P5);
   picked-up items go there.
5. **Level-placed actors** (rare for loot) keep their path id; their state changes (opened, destroyed) are messages,
   since a destroy did not reach the guest.
6. Keep `x2zone` / `x2garage` as the W1/W2 regression tests once suppression exists. Add checks that the guest has
   no own lootables and the host's replicated ones sit at the host's spots with the host's contents.
