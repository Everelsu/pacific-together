# Spike X6: Steam lobby and P2P messages under appid 1458140 (groundwork)

Question: can our C++ layer use the game's own Steam session (appid 1458140, `steam_api64.dll` already initialised by
the game) for a friends-only lobby, rich presence and `ISteamNetworkingMessages`, and carry UE's traffic over it?

Code: `native/PacificTogetherNative/steam.cpp` (Lua functions `PTNative_Steam*`), the tunnel's Steam link in
`transport.cpp` (`PTNative_TunnelSteam`). Scenarios: `steamsolo` (one account, automated), `steamhost` + `steamguest`
(two accounts on two PCs, the human test below). Native layer 0.0.3, UE4SS 3.0.1-1181-g83330635.

## How it is wired

- The DLL takes `GetModuleHandle("steam_api64.dll")` (never `LoadLibrary`), resolves the flat exports (`SteamAPI_SteamUser_v022`,
  `SteamFriends_v017`, `SteamMatchmaking_v009`, `SteamUtils_v010`, `SteamNetworkingMessages_SteamAPI_v002`,
  `SteamNetworkingUtils_SteamAPI_v004` and the `SteamAPI_I*` methods). It never calls `SteamAPI_Init` or
  `ManualDispatch_Init`; async results (`LobbyCreated_t` 513, `LobbyEnter_t` 504) are polled with
  `ISteamUtils::IsAPICallCompleted/GetAPICallResult` from Lua's game-thread loop.
- **Off by default**: every `PTNative_Steam*` function returns nil until Lua calls `PTNative_SteamEnable(true)`, which also
  checks `GetAppID() == 1458140` and calls `InitRelayNetworkAccess`.
- Lua API: `SteamEnable(bool)`, `SteamId()`, `SteamRelayStatus()`, `SteamCreateLobby(max)` (friends-only),
  `SteamJoinLobby(id)`, `SteamLobby()` -> id, status, `SteamLobbyMembers()` -> owner, members, `SteamLobbyData(k[, v])`,
  `SteamLeaveLobby()`, `SteamRichPresence(k, v)` -> ok, own value read back (no args = clear), `SteamFriendLobby()` ->
  lobby, friend (first friend in this game who is in a lobby), `SteamSend(id, channel, text, reliable)` -> EResult,
  `SteamReceive(channel)` -> from, text, `SteamAccept(id)`.
- Tunnel over Steam: `PTNative_TunnelSteam(0)` on both sides, the guest maps `PTNative_TunnelPeer("10.77.0.1",
  "steam:<host id>")` and opens `10.77.0.1:<port>`; UE packets become unreliable no-Nagle messages on channel 0 (see X5).

## Observations (steamsolo, one account)

Runs (local/test-results): `20261019-192832-laneA-steamsolo` (10/10 checks, first version), `20261019-193150-laneA-steamsolo`
(15/15, with the burst), `20261019-200032-laneA-steamsolo` (15/15, final), mutations `20261019-193502-...-steamsolo-nosteam`
(8/15; showed `steam_lobby_owner_me` passing with nil == nil, fixed), `20261019-200408-...-steamsolo-nosteam` (7/15 as
intended: every check after `steam_off_by_default` FAILs), `20261019-193645-...-steamsolo-steamearly` (14/15 as intended:
only `steam_off_by_default` FAILs). SteamIDs and lobby ids are in the local logs only.

- `steam_api64.dll` is loaded in the game process; all 31 flat exports resolve; every interface getter returns non-null;
  `ISteamUtils::GetAppID()` = 1458140 (the test copies carry `steam_appid.txt` 1458140).
- Before `PTNative_SteamEnable(true)` every Steam function returns nil (`steam_off_by_default`).
- `ISteamUser::GetSteamID` returns our 7656119... id.
- `GetRelayNetworkStatus` after `InitRelayNetworkAccess`: 3 (attempting) for ~3 s, then 100 (current) in every run.
- `CreateLobby(FriendsOnly, 2)`: result `k_EResultOK` within ~1 s, polled through `IsAPICallCompleted` /
  `GetAPICallResult` with no callback registered; we are the owner and the only member; `SetLobbyData` /
  `GetLobbyData` round-trips.
- `SetRichPresence("status", ...)` and `("connect", "+connect_lobby <lobby id>")` return true, and
  `GetFriendRichPresence(own id, key)` reads our own values back; after `ClearRichPresence` it reads "". `LeaveLobby`
  leaves `PTNative_SteamLobby()` nil.
- `SendMessageToUser` to our own SteamID: reliable and unreliable both return 1 (OK) and both arrive on channel 1 with
  our id as sender within the 10 s wait; a burst of 50 unreliable sends on channel 2: 50 OK, 50 received.
- **The first unreliable send, right after the first reliable one, blocked the game thread: 1828 ms
  (`20261019-193150`) and 6421 ms (`20261019-200032`)** (`PT|native steam slow send`). The other 51 sends were under 50 ms.
- Not tested alone: lobby join, friend lookup, a second account, the tunnel over Steam between two processes (two games
  on one account share one SteamID, so they cannot address each other).

## Derived

- The game's own Steam session works for us under appid 1458140 with no init of our own: lobby, lobby data, rich
  presence, the relay network and the messages API all answer, and async results can be polled without registering
  callbacks. Nothing here needs Spacewar 480.
- `SendMessageToUser` can stall for seconds while a session to a peer is being set up. In the tunnel it runs inside the
  game's `sendto`, so M6 must not send on the game thread before the session is up: warm it first (the human test
  echoes over channel 1 before any UE traffic) and/or move Steam sends to a worker thread.

## Guesses

- Two accounts on two PCs will see each other's lobby through `GetFriendGamePlayed` (Steam fills `m_steamIDLobby` for
  friends-only lobbies). Not checked: needs a second account.
- The SessionRequest callback (1251) is not needed when the host greets each new lobby member with a message (sending
  implicitly accepts); `steamhost` also calls `AcceptSessionWithUser` every 0.5 s in case.

## Unknowns

- Relay between two real accounts on different networks under this appid (the solo run only proves the local relay
  status and loopback delivery).
- Whether `+connect_lobby` / "Join Game" from the friends list starts the test copy or the real install (it starts the
  real install through Steam, so the mod would have to be installed there; out of scope for this spike).
- Message size and rate limits for UE packets over SDR (UE sends up to ~1 KB packets at net tick rate).
- Disconnect detection: Messages has no close notification; the tunnel's 1 s probes give the data, nothing acts on it yet.


## Human two-account test (two PCs, both with Pacific Drive on Steam, the two accounts are Steam friends), about 15 minutes

Roles: **PC A = host** (ikeepcalm), **PC B = guest** (Djecka). This tests the real mod's Steam join (M6, `docs/spikes/PT2-steam.md`:
`steam.lua`, UE traffic over `ISteamNetworkingMessages`). Both sides run the test copies made by `setup-test.ps1`
(`-NotInstalled`); the real install and saves are not touched. The old `steamhost` / `steamguest` scenarios (hand-driven natives)
still exist but are no longer the test.

### Once, on each PC (about 5 minutes)

1. Steam running and logged in with that PC's own account, game installed on build 21896301 (exe hash in `CLAUDE.md`).
2. Clone the repo, check out the commit of this work. Put the pinned UE4SS zip `zDEV-UE4SS_v3.0.1-1181-g83330635.zip`
   (SHA-256 `82378CD7F679D055026286F11347355AC67C712F21EB892060C902BB0184B907`) into `local\cache\ue4ss\`.
3. The native DLL of the same commit in `mod\PacificTogetherNative\dlls\main.dll` (build with `tools\build-native.cmd`, or copy
   it from the other PC). After a run, `UE4SS.log` shows `PT|native steam callback 333 registered` (callbacks work).
4. `powershell -File tools\setup-test.ps1` (makes `C:\PacificTogetherTest\client1`; only `client1` is used).

### The run

5. PC A: `powershell -File tools\run-test.ps1 -Scenario steamplayhost -Clients 1 -Seconds 1800` (windowed). Wait until the
   window shows the garage and `client1\PenDriverPro\Binaries\Win64\ue4ss\UE4SS.log` has `PT|steam lobby=<id> port=...`
   (about a minute).
6. PC B, look only: Steam friends list shows the host in Pacific Drive with "Join Game". **Do not click it** in this run
   (that starts PC B's real install, which has no mod).
7. PC B: `powershell -File tools\run-test.ps1 -Scenario steamplayguest -Clients 1 -Seconds 1800`. The guest scenario finds the
   friend's lobby through the friends list (fallback: `$env:PT_STEAM_LOBBY = "<id from PC A's log>"` in the same window first),
   gives the mod the text `+connect_lobby <id>` (what Join game puts on the command line), and the mod joins the lobby,
   warms the Steam session and connects. Both stay in the garage two minutes.
8. Both runners print a summary and a results folder (`local\test-results\<stamp>-steamplayhost` / `-steamplayguest`).
   Pass = every check PASS on both: host `steam_lobby_on_load`, `steam_rich_presence_connect`, `host_guest_joined`,
   `host_own_name_is_persona`, `host_guest_held`, `tunnel_carried_host`; guest `steam_found_friend_lobby`, `steam_joined_lobby`,
   `steam_tunnel_peer_mapped`, `guest_connected_garage`, `guest_own_name_is_persona`, `guest_still_connected`, `tunnel_carried_guest`.
9. Optional invite path (callback while the game runs): run PC B's step 7 as `$env:PT_STEAM_WAIT_INVITE = "1"` first (the guest
   scenario then feeds the mod nothing). PC A opens the overlay (Shift+Tab) and invites PC B's account (or PC B clicks Join Game
   in the friends list: Steam hands a running game of that appid the request instead of starting it). PC B accepts. The log has
   `PT|steam event join_lobby ...` (or `join_connect`), then the same join. If Steam still starts the real install on a click,
   note it and say so.
10. Optional, real "Join game" with the game closed: only if the owner installs the mod into the real game
    (`tools\package`). Then close the game on PC B, click Join Game on the friend: Steam starts the game with `+connect_lobby <id>`;
    the log has `PT|steam command line join lobby=<id>`. This one touches the real install and is the owner's call.

### What to send back

- Both results folders (zip them; they contain SteamIDs and the lobby id, keep them out of git).
- From the logs: lines with `PT|steam`, `PT|native steam`, `PT|native tunnel`, `PT|info tunnel final` (`rtt`/`rttAvg` are the
  tunnel's own round trip over Steam), any `slow send`, and the name lines (`PT|info steam persona=... names=...`: the guest on
  the host must carry the guest's Steam name, not its PC name).
- What steps 6 and 9 showed, and both PCs' networks (same LAN or not).

Verdict: groundwork done (one account), and the mod side of the join is built and tested as far as one account allows
(`steamsession`, `docs/spikes/PT2-steam.md`). Relay between two real accounts, the friends-list lookup and Steam delivering the
join request are what the steps above prove.
